# Single publish rejected for a partition key over its cap

The value an event type's `partition_key` pointer resolves to is at most 1024 bytes in its JSON string form (escapes counted, quotes not). The ingest outbox row stores the key beside the event, so a longer key is rejected `400` before anything is written. The body names the key's size and the cap, never the key.

## Setup

- Event type `gts.cf.core.events.event.v1~acme.orders.keyed.v1~` is registered with `partition_key` `/data/k`, and its `data` schema declares `k` a string.

## Request

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "e0000000-0000-0000-0000-000000000208",
  "type": "gts.cf.core.events.event.v1~acme.orders.keyed.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-42",
  "subject_type": "gts.acme.shop.orders.order.v1~",
  "occurred_at": "2026-05-29T10:10:00Z",
  "data": { "k": "...1025 bytes..." }
}
```

(The `data.k` string is 1025 bytes; abbreviated here.)

## Expected response

- `400 Bad Request` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/v1/events",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "events[0].partition_key",
        "description": "1025 bytes, over the limit of 1024",
        "reason": "partition_key_too_long"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No event is admitted.
