# Single publish rejected for an event over the size limit

An event's encoding (its whole JSON: `data`, `trace_parent`, `meta` and every other member) is at most 60 KiB (61,440 bytes). A larger event is rejected `413` after the envelope field checks (`source`, `subject`, `trace_parent`, `type`) and before the event type is looked up. The body names the event's size and the limit, never its content.

## Setup

- Event type `gts.cf.core.events.event.v1~acme.orders.created.v1~` is registered.

## Request

```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "id": "e0000000-0000-0000-0000-000000000207",
  "type": "gts.cf.core.events.event.v1~acme.orders.created.v1~",
  "tenant_id": "<tenant-uuid>",
  "source": "order-service",
  "subject": "order-42",
  "subject_type": "gts.acme.shop.orders.order.v1~",
  "occurred_at": "2026-05-29T10:10:00Z",
  "data": { "pad": "...a string that makes the event encode to 61,500 bytes..." }
}
```

(The `data.pad` string is abbreviated here.)

## Expected response

- `413 Content Too Large` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 413,
  "detail": "Request validation failed",
  "instance": "/v1/events",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "events[0]",
        "description": "61500 bytes encoded, over the limit of 61440",
        "reason": "event_too_large"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No event is admitted.
