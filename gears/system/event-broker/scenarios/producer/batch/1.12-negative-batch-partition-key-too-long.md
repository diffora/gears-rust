# Batch rejected for one partition key over its cap

One event of a `:batch` whose resolved partition key is over 1024 bytes rejects the whole batch `400`, naming that event's position.

## Setup

- Event type `gts.cf.core.events.event.v1~acme.orders.keyed.v1~` is registered with `partition_key` `/data/k`, and its `data` schema declares `k` a string.

## Request

The second event's `data.k` is 1025 bytes.

```http
POST /v1/events:batch HTTP/1.1
Host: broker.example.com
Authorization: Bearer <tenant-token>
Content-Type: application/json

{
  "events": [
    {
      "id": "e0000000-0000-0000-0000-000000001501",
      "type": "gts.cf.core.events.event.v1~acme.orders.keyed.v1~",
      "tenant_id": "<tenant-uuid>",
      "source": "order-service",
      "subject": "order-42",
      "subject_type": "gts.acme.shop.orders.order.v1~",
      "occurred_at": "2026-05-29T10:11:00Z",
      "data": { "k": "order-1" }
    },
    {
      "id": "e0000000-0000-0000-0000-000000001502",
      "type": "gts.cf.core.events.event.v1~acme.orders.keyed.v1~",
      "tenant_id": "<tenant-uuid>",
      "source": "order-service",
      "subject": "order-42",
      "subject_type": "gts.acme.shop.orders.order.v1~",
      "occurred_at": "2026-05-29T10:11:01Z",
      "data": { "k": "...1025 bytes..." }
    }
  ]
}
```

(The second `data.k` string is 1025 bytes; abbreviated here.)

## Expected response

- `400 Bad Request` (`PD`)

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/v1/events:batch",
  "trace_id": "<request-trace-id>",
  "context": {
    "field_violations": [
      {
        "field": "events[1].partition_key",
        "description": "1025 bytes, over the limit of 1024",
        "reason": "partition_key_too_long"
      }
    ],
    "resource_type": "gts.cf.core.events.request.v1~"
  }
}
```

## Side effects

- No event from the batch is admitted.
